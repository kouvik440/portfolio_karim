# Rédaction d'un portfolio de développeur crédible

## Hero

Modèle : `Je conçois et développe des applications web fiables, rapides et agréables à utiliser.` Remplacer par une proposition de valeur personnelle si l'utilisateur fournit sa spécialité. Pour un profil full-stack, mentionner les technologies vraiment maîtrisées (Laravel, React, Django REST, PostgreSQL selon expérience réelle). Éviter : « expert mondial », « 10 ans d'expérience » sans preuve.

## Projets

Chaque projet doit raconter :
- le contexte et le problème utilisateur ;
- l'objectif et les responsabilités personnelles ;
- la solution et les choix techniques ;
- les défis et compromis ;
- un résultat **vérifié** et le lien de démo/repository si partageable.

Si un lien est privé, expliquer sans révéler de secret. Pas de faux logos d'entreprises ni de captures inventées données comme réelles.

## Compétences

Catégoriser, limiter les badges à des technologies pertinentes et réellement utilisées. Expliquer la pratique (ex. « Création d'API REST ») plutôt que de multiplier de simples logos.

## Contact

Mettre un appel à l'action orienté discussion : « Parlons de votre projet ». Formulaire facultatif ; préférer un email visible uniquement si l'utilisateur l'autorise. Par défaut, anonymiser les données des exemples.

## Microcopy

- CTA primaire : « Découvrir mes projets ».
- CTA secondaire : « Me contacter ».
- Projets vides : « De nouveaux projets arrivent. » (uniquement si vrai), sinon masquer.
- Confirmation : « Votre message a bien été envoyé. » uniquement quand le backend confirme la réussite.
- Erreur : « Impossible d'envoyer le message pour le moment. Réessayez. »
